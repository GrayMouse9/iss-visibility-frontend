# Точки наблюдения МКС — React

ЛР6 по дисциплине «Разработка интернет-приложений», вариант 18.
React SPA для просмотра и публикации точек наблюдения МКС. Фиксированный макет
390 × 844 перенесён из ЛР2 и ЛР5. Четыре страницы: лента, плитка, вход и добавление.

## Запуск

Проверено с Node.js 24 и npm 11.

```bash
npm ci
npm run dev
```

Фронтенд: http://localhost:5173. Если порт занят, использовать адрес, напечатанный Vite.
Для работы с реальными данными запустить зависимости и Go API в соседнем бэкенде:

```bash
cd ../iss-visibility-backend
docker compose up -d
go run ./cmd/iss-visibility
```

Существующую БД не нужно перезаполнять. `go run ./cmd/seed` очищает таблицы и нужен
только для отдельной первоначальной подготовки окружения. Текущие учётные записи
можно использовать для входа. React ЛР6 не вызывает регистрацию; существующие
аккаунты и метод регистрации бэкенда ЛР4 сохранены.

Без Go API публичные лента и плитка переходят на локальные mock-данные и локальные
медиа. Это резерв только для гостя при сетевой ошибке, таймауте или 502/503/504.
Реальная ошибка API 400/401/403/404/500 не маскируется mock-данными. Создание,
публикация, лайки и удаление требуют работающего сервиса и авторизации.

## Страницы

| Адрес | Содержимое |
|---|---|
| `/feed`, `/feed/:id` | Одна точка: видео, описание, координаты, лайки, переход «Далее» |
| `/observation_points` | Каталог, фильтр минимальной широты, удаление своих точек |
| `/login` | Вход под существующей учётной записью |
| `/observation_points/new` | Создание черновика с файлами, затем публикация описания и координат |

Корень и неизвестные маршруты перенаправляют на `/feed`. Неизвестный ID показывает
сообщение и ссылку в плитку. Прямое открытие добавления гостем ведёт на страницу входа.

В меню четыре пункта: «Лента», «Добавление», «Плитка», «Войти»/«Выход».
Гостю недоступно добавление. Лайк доступен в ленте после входа, удаление в плитке —
только при серверном `is_mine: 1`. Сервер дополнительно проверяет права на операции.
Удаление требует подтверждения. Счётчик лайков и `liked` обновляются после успешного
ответа API, без фиктивного оптимистического успеха.

## API и прокси

Браузер обращается к своему origin. В `vite.config.ts` настроены два маршрута:

| Префикс | Куда пересылается |
|---|---|
| `/api` | `http://localhost:3001/api` с сохранением пути |
| `/s3` | `http://localhost:9200`, префикс `/s3` удаляется |

Например, браузер запрашивает `/api/observation_points?min_latitude=0` и
`/s3/iss-visibility/observation_point_11_image.jpg`. API возвращает исходный
`image_url`/`video_url`; `observationPointMediaUrl` переводит путь объекта в прокси
перед отображением. Публичные mock-медиа из `/media` не преобразуются.

CORS в Vite отключён (`server.cors: false`, `preview.cors: false`). Прокси удаляет
заголовки `Access-Control-*` и только значение `Origin` из `Vary`, если их прислал
upstream. Остальные заголовки и данные сохраняются. Браузер использует свой origin,
а API и S3 доступны через два маршрута прокси.

React ЛР6 использует ровно **9 операций**: 7 методов точек через сгенерированный
Axios-клиент и thunk плюс 2 ручных Axios POST (`/users/login`, `/users/logout`).
Бэкенд ЛР4 по-прежнему содержит 10 API-операций, включая регистрацию. React её не
вызывает; сохранение этого серверного метода не добавляет десятую операцию клиенту.

Каталог фильтруется сервером по `min_latitude`. Ползунок меняет `latitudeInput` в Redux,
а «Найти» применяет его к `minLatitude` и вызывает запрос. Повторное применение того
же значения обновляет данные БД. Значения сохраняются при переходах между страницами.
«Выход» сбрасывает оба значения в −90. Изменение только ползунка не меняет выдачу.

У API нет GET точки по ID. Для `/feed/:id` клиент получает полный опубликованный
каталог, определяет предшественника и использует существующий
`GET /observation_points/feed?after=...`. На первой точке `after` не передаётся.
«Далее» учитывает пропуски ID и замыкает ленту независимо от фильтра плитки.
Если запись исчезла между запросами, показывается ошибка, а не другая точка под тем же URL.

Прокси Vite предназначен для локальной демонстрации через `npm run dev`.
Для размещения собранного `dist` потребуется такой же reverse proxy на сервере;
`npm run preview` самостоятельно маршруты Vite dev-server не предоставляет.

## Swagger → Axios → Redux Thunk

Копия реальной спецификации бэкенда хранится в `openapi/swagger.json`. Из неё
генератор выбирает только семь операций `/observation_points`. Вход/выход и
регистрация в сгенерированный клиент React не попадают. Генерация
воспроизводится без запущенного API:

```bash
npm run generate-api
```

Скрипт `scripts/generate-api.mjs` использует `swagger-typescript-api` и
`httpClientType: 'axios'`. Результат — `src/api/generated/ObservationPointsApi.ts`.
При изменении контракта скопировать актуальный Swagger и повторить генерацию:

```bash
cp ../iss-visibility-backend/docs/swagger.json openapi/swagger.json
npm run generate-api
```

Сгенерированный файл вручную не редактируется. В `src/api/client.ts` создаётся
клиент с `baseURL: '/api'`. Все обращения домена точек выполняются в
`src/store/observationPointsSlice.ts` через тематические thunk:

- `loadObservationPoints`, `loadObservationPointFeed`, `loadObservationPointDraft`;
- `createObservationPointDraft`, `publishObservationPoint`;
- `deleteObservationPoint`, `setObservationPointLike`.

Обработчики pending/fulfilled/rejected сохраняют данные, loading и ошибку.
requestId не позволяет устаревшему ответу заменить актуальное состояние или
восстановить пользовательские данные после выхода. Читающие запросы отменяются
при уходе со страницы. На время запроса анимация закрывает приложение; fieldset
блокирует кнопки, `inert` блокирует также ссылки и ввод с клавиатуры.

## Вход и выход — ручной Axios

По заданию ЛР6 авторизация не использует thunk и сгенерированные методы users.
`LoginPage.tsx` вызывает `authenticationApi.post('/login', ...)`, сохраняет JWT
и вручную отправляет `loggedIn`. Это один из двух ручных Axios-вызовов.
`BottomNavigation.tsx` вызывает `/logout`, очищает
cookie и отправляет `loggedOut`. Если выход не дошёл до сервера, интерфейс сообщает
об ошибке; 401 означает, что токен уже недействителен, и локальный выход завершается.

JWT хранится в cookie `iss_access_token` с Path=/, SameSite=Lax и временем жизни
из ответа login. Cookie записывает фронтенд, поэтому она доступна JavaScript и
вкладке Application; это учебная схема для показа ЛР6. В текущем Go API токен
принимается в `Authorization: Bearer <JWT>`, а не непосредственно из Cookie.
Клиент передаёт Bearer только из авторизованного состояния Redux.

После F5 Redux создаётся заново: меню «Войти», `isAuthenticated: false`, `token: null`.
Cookie при этом остаётся, но авторизованный интерфейс из неё автоматически не
восстанавливается. Гостевые API-запросы не предъявляют сохранённый JWT.
Для показа в Postman можно скопировать JWT из Application → Cookies и вставить
как Bearer Token: каталог вернёт `is_mine: 1` у собственных опубликованных точек.
Для нового входа после F5 используются логин и пароль.

При настоящем «Выходе» сервер отзывает предъявленный JWT через Redis, затем
фронтенд очищает cookie, данные пользователя, черновик и фильтры. Это отличается
от F5, который не вызывает logout.

## Структура

```text
src/main.tsx                              Provider и BrowserRouter
src/App.tsx                               маршруты, общая загрузка, ошибки
src/store/store.ts                        configureStore, типизированные hooks
src/store/authSlice.ts                    состояние пользователя, обычные actions
src/store/observationPointsSlice.ts        фильтр, данные, thunk, состояния запросов
src/api/client.ts                         Axios-клиенты, заголовки, ошибки
src/api/authentication.ts                 запись и удаление cookie
src/api/generated/ObservationPointsApi.ts  сгенерированный API
src/pages/                                четыре страницы
src/components/                           навигация, карточки, видео, фильтр
src/mocks/observationPoints.ts             гостевая локальная коллекция
src/utils/                                медиа и координаты
scripts/generate-api.mjs                   генерация из Swagger
openapi/swagger.json                      снимок контракта Go API
public/media/                             фото и MP4 для mock/fallback
```

В store зарегистрированы `auth` и `observationPoints`. Последний содержит фильтр,
`catalog`, `feed`, `draft`, `mutation`; у каждого запроса есть loading/error/requestId.
Файлы формы не хранятся в Redux: `File` передаётся аргументом thunk создания.
После создания файлы уже в MinIO, а черновик перечитывается с сервера при повторном
открытии страницы. При ошибке загрузки файлов клиент проверяет, не остался ли
черновик на сервере, чтобы не предлагать второй.

## Проверки

```bash
npm run generate-api
npm run build
npm run lint
npm run check:lab6
npx playwright install chromium
npm test
```

Playwright запускает Vite на свободном порту 5175. Настройка добавляет localhost и
127.0.0.1 в обход системного HTTP-прокси. Можно задать установленный Chromium через
`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.

`npm run check:lab6` проверяет ровно семь операций в generated и два ручных вызова,
а также реальные HTTP-ответы Vite и обоих прокси с заголовком Origin. В тестовом
upstream намеренно включены CORS-заголовки: проверка подтверждает, что они не
попадают в ответы браузеру, а фильтр, Bearer и содержимое изображения сохраняются.

Тесты подменяют только URL `/api/...`, не клиентские файлы `src/api`.
Проверяются гостевой mock, fallback медиа, фильтрация, переходы, F5/cookie,
вход и ошибки входа, выход/сброс фильтра, свои/чужие точки, лайки, multipart-создание,
публикация нулевых координат, ошибки API и блокировка кнопок.

Материалы сдачи находятся вне Git-репозитория в соседней папке `reports/ЛР6`:
РПЗ, единый файл диаграмм и порядок показа с ровно 16 местами для собственных
скриншотов студента. Коммиты, push и публикацию ветки выполняет студент.
